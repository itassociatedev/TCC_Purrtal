# TCC Purrtal Asset Management

**Purpose:** Working guide to the asset-management module in this repository. This reflects the checked-in implementation on `project-brave` at commit `1bf60b7` (25 November 2026). It is a code review and operating map, not a claim that every workflow has been exercised against a live tenant or production database.

## What the module does

The module manages tagged assets, inventory details, assignment and accountability, spreadsheet imports, CSV/PDF exports, and asset photos. Photo changes use an IT review queue and can store approved files in OneDrive through Microsoft Graph. Staff can view their assigned personal and shared assets and download an accountability form.

## User workflows

### Asset inventory

- **Asset overview** is served by `Admin/AssetController@index` and rendered by `resources/js/Pages/Admin/Assets.jsx`.
- **Add asset** accepts the asset tag, name, category, classification, branch, department, area, supplier, purchase and warranty dates, condition, quantity, value, status, model, serial number, color, and optional image.
- **Edit asset** updates inventory fields. An edit submitted with an image is staged for photo review; the live record stays unchanged until approval.
- **View asset** opens the detail modal. It includes specifications, assignment, procurement and financial information, and an authenticated photo view when an approved image exists.
- **Delete asset** removes the record. The current deletion flow does not remove the corresponding approved OneDrive file; see the audit notes.
- The `asset_tag` identifies the inventory item. It is separate from `serial_no` and `model_no`.

### Accountability and transfers

- The accountability type is **Personal** or **Shared**. It is stored on the asset and on each `asset_user` assignment row.
- Personal accountability selects one employee. Shared accountability selects multiple employees and marks one pivot row as team leader.
- The accountability editor can auto-select employees using branch and department. It matches the staff branch/department values against the entered values after trimming and lowercasing. Branch membership can come from a user's branch field or branch memberships.
- Changing scope replaces the selected team and chooses a leader candidate based on position labels (team leader, supervisor, manager/head, then other). The manager can change the leader and individual members before saving.
- Bulk transfer can update accountability type, assignees, leader, branch, and department for selected assets. Unassign clears pivot assignments, sets status to **In Storage**, and clears the legacy single-user fields.
- The staff **My Assets** view includes records assigned through the legacy `user_id` field or the `asset_user` pivot. It separates personal from shared assets and offers a PDF acknowledgment form.
- The accountability PDF is generated by `AccountabilityPdfService`; unit tests cover empty lists, long lists with continuation pages, and long remarks.

### Import, export, and history

- **Workbook import** (`importSpreadsheet`) accepts CSV, TXT, XLSX, and XLS up to 20 MB. It scans the first 60 rows for Name and Tag columns, identifies branch from tag, row, workbook metadata, or a user-selected fallback, then creates or updates records by case-insensitive asset tag.
- Workbook imports create a batch with a copy of the uploaded file, per-record before-values or created-record markers, and a post-import hash. Full managers can download batch files and reverse a batch if the assets still match their post-import hashes.
- A separate **legacy CSV import** (`import`) remains available in the controller. It uses a simpler parser and has no batch/reversal record. Confirm which import action the UI invokes before relying on reversal/history.
- **CSV export** includes inventory fields, computed depreciation/book values, and a photo link. Exports are logged in system logs.
- **PDF masterlist** is generated for selected asset IDs. The asset overview also contains a client-side spreadsheet export/template flow.
- The export code currently uses straight-line depreciation over 60 months. Finance should confirm this rule before treating exported accumulated depreciation or book value as authoritative.

### Asset photo capture and review

- Asset entry and the separate photo capture page accept JPG/JPEG, PNG, or WebP images up to 10 MB for photo submissions. The asset-create/edit form's image validation is 5 MB.
- A submission is stored in private Laravel storage and remains pending. New assets submitted with a photo are drafts; replacement details and photos also remain staged until approved.
- IT reviewers can preview, approve, reject with an optional reason, or process a selection in bulk. Rejected history is scoped to the submitter for most users; IT interns and full managers can see wider history.
- When OneDrive is enabled, approval gets a Graph token using client credentials, uploads the photo to the branch folder using a tag-and-revision filename, then records the Graph item ID and URL. The UI retrieves approved image bytes through an authenticated app endpoint.
- Branch folder mapping supports Greenhills (`GH`), Makati (`MKT`), and Alabang (`ALB`). Unknown branches fail closed rather than routing the file to an arbitrary folder.
- Replacement uploads use a new versioned file. The previous Graph file is removed only after the new asset photo reference is committed successfully.
- OneDrive environment variables and Entra setup are described in [ONEDRIVE_ASSET_PHOTOS.md](ONEDRIVE_ASSET_PHOTOS.md). Do not put credentials in frontend code or commit `.env` secrets.

## Access control

- All shown routes require authentication. Staff asset routes use the authenticated route group.
- Photo capture/submission checks `AssetAccess::canEnter`; photo review/decision checks `canReviewPhotos`; approved-photo streaming checks `canViewOverview`.
- Admin asset routes also pass through `AdminMiddleware`. Asset entry/store has a narrower `canEnter` allowance; other asset management operations require the full-manager policy or an explicit module grant.
- The React overview has its own role-based display logic. Backend checks are the enforcement boundary; hiding a button in the UI is not authorization.
- Review role mappings before changing staff roles or Access Control settings. `AssetAccess` includes name-based full-manager exceptions as well as role/department checks, which is operationally sensitive and should eventually be moved to managed roles/permissions.

## Audit findings from code review

1. **Approved OneDrive images can be orphaned when assets are deleted.** Single and bulk delete only check Laravel's public storage and then delete the database asset. Approved Graph items are not removed. Import reversal can also delete a newly imported asset and cascade away its photo submission reference without deleting the Graph item. This can leave inaccessible files in OneDrive.
2. **Import batch reversal does not restore accountability pivot rows.** Workbook import updates asset columns such as `user_id` and `assigned_personnel`, but does not snapshot or sync `asset_user`. A reversal restores recorded asset fields only. If an imported update changes the legacy assignee, the pivot can remain inconsistent; if a created record had later photo/accountability changes that are not captured by the asset hash, those relations are outside the reversal check.
3. **The legacy CSV importer is materially less safe than the workbook importer.** It overwrites records by tag without creating a reversible batch, and it does not preserve the original workbook or before-values. Prefer workbook import and confirm the UI is not exposing the legacy path for routine imports.
4. **Depreciation is hard-coded in export/UI logic.** The current calculation assumes 60 months and straight-line depreciation. Confirm the accounting policy before using those values for reporting.
5. **Auto-selection depends on consistent directory data.** A user whose branch membership or department label differs from the scope entered will not be selected. Verify the organizational directory's branch and department values when investigating a missing team member or leader. The modal replaces the team when scope is applied, but an empty match is possible if directory data is incomplete or uses aliases.
6. **Authorization policies are split across middleware, `AssetAccess`, and frontend visibility checks.** Review their agreement when adding an asset action; avoid relying on the React checks alone. The name-based full-manager allowlist is a maintenance and audit concern.

These findings are based on static code tracing. No database or production data was changed as part of this review.

## Recommended follow-up

1. Add safe Graph-file cleanup for asset deletion, bulk deletion, and import reversal, with failure logging/retry behavior so database records are not lost if Graph is temporarily unavailable.
2. Extend import batch snapshots and reversal to cover accountability pivots and associated relations, or block reversal when those relations changed.
3. Retire or clearly gate the legacy CSV importer after confirming current UI usage.
4. Confirm and centralize the depreciation policy.
5. Add focused feature tests for personal/shared assignment replacement, changing department/branch and team leader, unassign, permissions on every mutation route, import updates/reversal with relations, and OneDrive delete/rollback behavior.
6. Validate the Entra app's least-privilege permission and selected-site grant in the intended tenant, then run photo approval and replacement tests against a dedicated test folder.
